# 15. Composant HeroBrand

> **Fichiers concernés**
> - `src/shared/components/HeroBrand/HeroBrand.tsx`
> - `src/shared/components/HeroBrand/HeroBrand.module.scss`

---

## Ce que fait ce composant

`HeroBrand` affiche le logo de l'entreprise en grand format dans la zone centrale de `PageLayout`. Son comportement change selon le viewport :

- **Mobile** : le logo remonte et empiète visuellement sur l'image de fond (effet "relevé")
- **Desktop** : le logo s'affiche normalement dans la colonne droite, sans décalage

C'est un composant sans props, sans état, sans logique : purement présentationnel.

---

## L'import de fichier avec apostrophe et espace

```typescript
import logo from "../../../assets/images/logo homecycl'home 750-750.webp";
```

Le nom de fichier contient deux caractères inhabituels : une **espace** et une **apostrophe**. En JavaScript/TypeScript, un import est une chaîne de caractères ordinaire — il suffit d'utiliser des **doubles guillemets** pour éviter d'avoir à échapper l'apostrophe (qui serait un problème entre simples guillemets).

Vite traite cet import comme n'importe quel asset : il résout le chemin, copie le fichier dans le dossier de build avec un hash de cache, et retourne l'URL finale. Le composant n'a pas à se préoccuper du chemin réel en production.

**Bonne pratique pour l'avenir :** nommer les assets sans espaces ni caractères spéciaux (`logo-homecyclhome-750.webp`) pour éviter ce genre de contournement.

## L'effet "relevé" sur mobile — `margin-top` négatif

```scss
.heroBrand {
    margin-top: -200px;
    position: relative;
    z-index: 1;

    @include desktop {
        margin-top: 0;
        position: static;
        z-index: auto;
    }
}
```

### Pourquoi `margin-top` négatif et pas `transform: translateY()` ?

Les deux déplacent visuellement l'élément vers le haut, mais leur effet sur le **flux du layout** est radicalement différent.

| Propriété | Effet visuel | Effet sur le flux flex |
|---|---|---|
| `transform: translateY(-200px)` | Monte de 200px | **Aucun** — l'espace occupé reste en place |
| `margin-top: -200px` | Monte de 200px | **Réduit** l'espace occupé de 200px |

Avec `transform`, le logo monterait visuellement, mais le "trou" de 200px resterait visible dans la section verte sous lui — `LoginForm` ne remonterait pas avec lui. Avec `margin-top` négatif, le logo ET l'espace qu'il consomme dans le layout remontent : `LoginForm` se repositionne naturellement juste en dessous du logo.

### Pourquoi `position: relative` et `z-index: 1` ?

Le `.topSection` (l'image de fond) et le `.contentSection` (la zone verte) sont deux éléments frères dans le flex du `PageLayout`. Sans `position: relative`, le navigateur ne peut pas attribuer un `z-index` à `.heroBrand` — `z-index` n'a d'effet que sur les éléments **positionnés** (relative, absolute, fixed, sticky).

Sans `z-index: 1`, le logo remonterait bien dans la zone de l'image, mais il passerait derrière le `.topSection` (puisqu'en flux normal, les éléments suivants dans le DOM passent au-dessus des précédents). Avec `z-index: 1`, le logo est garanti visible au-dessus de tout.

### Annulation sur desktop

```scss
@include desktop {
    margin-top: 0;
    position: static;
    z-index: auto;
}
```

Sur desktop, la structure de `PageLayout` change en grille 2 colonnes — l'effet de chevauchement n'a pas lieu d'être. On remet les valeurs à leur état par défaut :
- `margin-top: 0` : pas de décalage
- `position: static` : retire l'élément du contexte de positionnement
- `z-index: auto` : retire la couche de z-index explicite

## L'image 750×750 — pourquoi cette résolution ?

```tsx
import logo from "../../../assets/images/logo homecycl'home 750-750.webp";
```

On importe la version haute résolution (750px) même si le logo est affiché à 180px (mobile) ou 260px (desktop). Deux raisons :

1. **Écrans Retina / HiDPI** : sur un iPhone ou MacBook avec écran Retina, le navigateur utilise 2× à 3× la densité de pixels. Un logo de 180px CSS correspond à 360px–540px réels. La version 750px couvre cette densité sans pixelisation.

2. **Vite optimise** : en production, Vite peut appliquer de la compression (selon la configuration). Mieux vaut partir d'une source de qualité et laisser l'outil réduire que de partir d'une source trop petite.

## Intégration dans `Home.tsx`

```tsx
<PageLayout>
    <HeroBrand />
    <LoginForm />
</PageLayout>
```

`HeroBrand` est le **premier enfant** de `PageLayout`. L'espacement entre `HeroBrand` et `LoginForm` est géré par le `gap: $spacing-md` défini sur `.contentSection` dans `PageLayout.module.scss` — `HeroBrand` n'a pas à gérer son propre espacement inférieur.

C'est une application du principe de **responsabilité du parent** : c'est le conteneur (`PageLayout`) qui décide de l'espace entre ses enfants, pas les enfants eux-mêmes.
