### Qu'est-ce qu'un DTO ?

Un **DTO** (Data Transfer Object) est un objet qui définit la forme exacte des données attendues dans une requête HTTP. Il joue deux rôles :

- **Validation** — via `class-validator`, NestJS rejette automatiquement les requêtes mal formées avant même d'entrer dans le service
- **Documentation** — le DTO dit clairement "voilà ce que cet endpoint attend"

Le `ValidationPipe` global dans `main.ts` s'occupe de déclencher la validation automatiquement sur tous les endpoints.

### Ce qu'il faut créer

**`Backend/src/features/auth/dto/register.dto.ts`** :

```typescript
import { IsEmail, IsNotEmpty, IsString, Matches, MinLength } from 'class-validator';

export class RegisterDto {
    @IsString()
    @IsNotEmpty()
    nom: string;

    @IsString()
    @IsNotEmpty()
    prenom: string;

    @IsEmail()
    email: string;

    @IsString()
    @MinLength(8)
    password: string;

    @IsString()
    @Matches(/^(\+33|0)[1-9](\d{2}){4}$/)
    telephone: string;
}
```

**`Backend/src/features/auth/dto/login.dto.ts`** :

```typescript
import { IsEmail, IsNotEmpty, IsString } from 'class-validator';

export class LoginDto {
    @IsEmail()
    email: string;

    @IsString()
    @IsNotEmpty()
    password: string;
}
```

**`Backend/src/features/auth/dto/auth-response.dto.ts`** :

```typescript
export class AuthResponseDto {
    userId: string;
    role: string;
    prenom: string;
}
```

> ⚠️ **Mise à jour :** le champ `prenom` a été ajouté après la rédaction initiale de ce guide —
> le Header affiche le prénom de l'utilisateur connecté, il doit donc être disponible dès la
> réponse de login sans appel supplémentaire à `GET /users/me`.

Ce dernier DTO représente ce que le frontend reçoit après un login réussi — exactement ce qu'attend l'`AuthSession` côté React. On n'y met jamais de token ni de mot de passe.
