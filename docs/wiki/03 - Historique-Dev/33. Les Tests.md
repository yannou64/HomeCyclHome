## Étape 1 — Pourquoi on teste le service et pas autre chose ?

Dans NestJS, le flux d'une requête est :

```
Requête HTTP → Controller → Service → Prisma → BDD
```

Le **controller** ne fait que recevoir et déléguer — aucune logique à valider.  
**Prisma** est testé par ses propres mainteneurs — pas notre rôle.  
Le **service** c'est l'endroit où vit toute la logique métier : "est-ce que cet email existe déjà ?", "est-ce que le token a expiré ?", "est-ce que le compte est actif ?". C'est donc lui qu'on teste.

## Étape 2 — Le problème des dépendances

`AuthService` a besoin de 3 choses pour fonctionner :

```typescript
constructor(
    private readonly prisma: PrismaService,      // accès BDD
    private readonly jwtService: JwtService,      // génération tokens
    private readonly emailService: EmailService,  // envoi emails
)
```

Si on crée un vrai `AuthService` dans les tests, il va essayer de se connecter à PostgreSQL, d'envoyer de vrais emails, etc. C'est exactement ce qu'on veut éviter dans des **tests unitaires** — ils doivent être :

- **Rapides** (pas de réseau, pas de BDD)
- **Déterministes** (même résultat à chaque exécution)
- **Isolés** (un test ne dépend pas d'un autre)

La solution : les **mocks**. On remplace les vraies dépendances par des fausses qui simulent le comportement qu'on veut.

## Étape 3 — La structure d'un fichier de test Jest

Voici le squelette à écrire dans ton fichier :

```typescript
describe('AuthService', () => {

    describe('register', () => {
        it('devrait créer un utilisateur', () => { ... });
        it('devrait lever ConflictException si email déjà utilisé', () => { ... });
    });

    describe('login', () => {
        it('devrait lever UnauthorizedException si email inconnu', () => { ... });
        // ...
    });

});
```

- `describe` = groupe logique de tests (un par méthode)
- `it` = un test précis, une seule règle à la fois
- Le nom du `it` se lit comme une phrase : _"il devrait…"_

## Étape 4 — Mise en place du module de test NestJS

NestJS fournit `Test.createTestingModule()` — l'équivalent de `AppModule` mais pour les tests. Il instancie le service avec les dépendances qu'on lui donne.

Écris ceci dans ton fichier :

```typescript
import { Test, TestingModule } from '@nestjs/testing';
import { AuthService } from './auth.service';
import { PrismaService } from '../../../shared/prisma/prisma.service';
import { JwtService } from '@nestjs/jwt';
import { EmailService } from '../../email/email.service';

describe('AuthService', () => {
    let service: AuthService;

    beforeEach(async () => {
        const module: TestingModule = await Test.createTestingModule({
            providers: [
                AuthService,
                {
                    provide: PrismaService,
                    useValue: {
                        utilisateur: {
                            findUnique: jest.fn(),
                            create: jest.fn(),
                            update: jest.fn(),
                        },
                    },
                },
                {
                    provide: JwtService,
                    useValue: { sign: jest.fn() },
                },
                {
                    provide: EmailService,
                    useValue: { sendConfirmationEmail: jest.fn() },
                },
            ],
        }).compile();

        service = module.get<AuthService>(AuthService);
    });

    it('should be defined', () => {
        expect(service).toBeDefined();
    });
});
```

`jest.fn()` crée une fonction factice qui ne fait rien par défaut — on lui donnera un comportement test par test.

`beforeEach` recrée un module propre avant chaque test → pas de pollution entre tests.

---

Lance d'abord juste ça pour vérifier que la config fonctionne :

```bash
cd Backend && npm test -- --testPathPattern=auth.service
```

Si tu vois `✓ should be defined` en vert, la fondation est en place et on passe à l'écriture des vrais cas.

## Étape 5 — Premier cas : email déjà utilisé

C'est le cas le plus simple à écrire et le plus représentatif du pattern.

**Ce qu'on veut tester :** si `prisma.utilisateur.findUnique` retourne un utilisateur existant, `register()` doit lancer une `ConflictException`.

Voici comment simuler ce comportement avec un mock. Ajoute ce bloc dans ton `describe('AuthService')` :

```typescript
import { ConflictException } from '@nestjs/common';

describe('register', () => {
    it('devrait lever ConflictException si email déjà utilisé', async () => {
        // ARRANGE — on simule que Prisma trouve un utilisateur existant
        const prismaMock = module.get<PrismaService>(PrismaService);
        jest.spyOn(prismaMock.utilisateur, 'findUnique').mockResolvedValue({
            id: 'uuid-existant',
            email: 'test@gmail.com',
        } as any);

        // ACT + ASSERT — on vérifie que l'exception est bien levée
        await expect(
            service.register({
                prenom: 'Yannick',
                nom: 'Biot',
                email: 'test@gmail.com',
                telephone: '0612345678',
                password: 'motdepasse123',
            }),
        ).rejects.toThrow(ConflictException);
    });
});
```

**Trois concepts nouveaux ici :**

- `jest.spyOn(...).mockResolvedValue(...)` — on intercepte l'appel à `findUnique` et on lui dit _"retourne cette valeur"_. `mockResolvedValue` car c'est une promesse (`async`).
- `as any` — Prisma retourne un objet complet avec 15 champs, on ne fournit que ce dont le service a besoin pour décider.
- `rejects.toThrow` — pour tester qu'une promesse rejette avec une exception précise.

Pour accéder à `module` dans le test, il faut le déclarer au niveau du `describe` :

```typescript
let module: TestingModule;  // ← ajoute cette ligne à côté de `let service`
```

Et dans `beforeEach`, assigne-le avant `service` :

```typescript
module = await Test.createTestingModule({ ... }).compile();
service = module.get<AuthService>(AuthService);
```

## Étape 6 — Deuxième cas : inscription réussie

Ce test est plus intéressant car il faut simuler **plusieurs** appels Prisma en séquence :

```typescript
it('devrait créer un utilisateur et envoyer un email de confirmation', async () => {
    // ARRANGE
    const prismaMock = module.get<PrismaService>(PrismaService);
    const emailMock = module.get<EmailService>(EmailService);

    // findUnique retourne null → email disponible
    jest.spyOn(prismaMock.utilisateur, 'findUnique').mockResolvedValue(null);

    // create retourne l'utilisateur créé
    jest.spyOn(prismaMock.utilisateur, 'create').mockResolvedValue({
        id: 'nouvel-uuid',
        email: 'nouveau@gmail.com',
        prenom: 'Yannick',
    } as Utilisateur);

    // sendConfirmationEmail — on surveille qu'il est bien appelé
    const sendEmailSpy = jest
        .spyOn(emailMock, 'sendConfirmationEmail')
        .mockResolvedValue(undefined);

    // ACT
    const result = await service.register({
        prenom: 'Yannick',
        nom: 'Biot',
        email: 'nouveau@gmail.com',
        telephone: '0612345678',
        password: 'motdepasse123',
    });

    // ASSERT
    expect(result.message).toContain('Inscription réussie');
    expect(sendEmailSpy).toHaveBeenCalledTimes(1);
    expect(sendEmailSpy).toHaveBeenCalledWith(
        'nouveau@gmail.com',
        'Yannick',
        expect.any(String), // le token généré aléatoirement
    );
});
```

**Deux nouveaux concepts :**

- `mockResolvedValue(null)` — simule que l'email n'existe pas encore en base
- `expect.any(String)` — le token est généré aléatoirement (`crypto.randomBytes`), on ne peut pas prédire sa valeur. On vérifie juste que c'est une chaîne.

## Étape 7 — `confirmEmail` : 3 cas

On attaque la méthode suivante. Trois règles à tester :

```typescript
describe('confirmEmail', () => {

    it('devrait lever NotFoundException si token inconnu', async () => {
        const prismaMock = module.get<PrismaService>(PrismaService);
        jest.spyOn(prismaMock.utilisateur, 'findUnique').mockResolvedValue(null);

        await expect(service.confirmEmail('token-inconnu'))
            .rejects.toThrow(NotFoundException);
    });

    it('devrait lever BadRequestException si token expiré', async () => {
        const prismaMock = module.get<PrismaService>(PrismaService);
        jest.spyOn(prismaMock.utilisateur, 'findUnique').mockResolvedValue({
            id: 'uuid',
            email: 'test@gmail.com',
            token_expires_at: new Date('2000-01-01'), // date dans le passé → expiré
        } as Utilisateur);

        await expect(service.confirmEmail('token-expiré'))
            .rejects.toThrow(BadRequestException);
    });

    it('devrait activer le compte si token valide', async () => {
        const prismaMock = module.get<PrismaService>(PrismaService);

        jest.spyOn(prismaMock.utilisateur, 'findUnique').mockResolvedValue({
            id: 'uuid',
            email: 'test@gmail.com',
            token_expires_at: new Date('2099-01-01'), // date dans le futur → valide
        } as Utilisateur);

        const updateSpy = jest
            .spyOn(prismaMock.utilisateur, 'update')
            .mockResolvedValue({} as Utilisateur);

        const result = await service.confirmEmail('token-valide');

        expect(result.message).toContain('confirmé');
        expect(updateSpy).toHaveBeenCalledWith({
            where: { id: 'uuid' },
            data: {
                is_actif: true,
                email_confirmation_token: null,
                token_expires_at: null,
            },
        });
    });

});
```

Ajoute les imports manquants en haut du fichier :

```typescript
import { BadRequestException, ConflictException, NotFoundException } from '@nestjs/common';
```

Lance et montre le résultat.

## Étape 8 — `login` : 4 cas

```typescript
describe('login', () => {

    it('devrait lever UnauthorizedException si email inconnu', async () => {
        const prismaMock = module.get<PrismaService>(PrismaService);
        jest.spyOn(prismaMock.utilisateur, 'findUnique').mockResolvedValue(null);

        await expect(
            service.login({ email: 'inconnu@gmail.com', password: 'mdp' }, mockRes()),
        ).rejects.toThrow(UnauthorizedException);
    });

    it('devrait lever UnauthorizedException si mot de passe incorrect', async () => {
        const prismaMock = module.get<PrismaService>(PrismaService);
        jest.spyOn(prismaMock.utilisateur, 'findUnique').mockResolvedValue({
            id: 'uuid',
            email: 'test@gmail.com',
            password_hash: await bcrypt.hash('bon-mot-de-passe', 12),
            is_actif: true,
        } as Utilisateur);

        await expect(
            service.login({ email: 'test@gmail.com', password: 'mauvais-mdp' }, mockRes()),
        ).rejects.toThrow(UnauthorizedException);
    });

    it('devrait lever ForbiddenException si compte non confirmé', async () => {
        const prismaMock = module.get<PrismaService>(PrismaService);
        jest.spyOn(prismaMock.utilisateur, 'findUnique').mockResolvedValue({
            id: 'uuid',
            email: 'test@gmail.com',
            password_hash: await bcrypt.hash('motdepasse123', 12),
            is_actif: false, // ← compte non confirmé
        } as Utilisateur);

        await expect(
            service.login({ email: 'test@gmail.com', password: 'motdepasse123' }, mockRes()),
        ).rejects.toThrow(ForbiddenException);
    });

    it('devrait retourner userId et role si credentials valides', async () => {
        const prismaMock = module.get<PrismaService>(PrismaService);
        const jwtMock = module.get<JwtService>(JwtService);

        jest.spyOn(prismaMock.utilisateur, 'findUnique').mockResolvedValue({
            id: 'uuid-valide',
            email: 'test@gmail.com',
            password_hash: await bcrypt.hash('motdepasse123', 12),
            is_actif: true,
            role: 'client',
        } as Utilisateur);

        jest.spyOn(prismaMock.utilisateur, 'update').mockResolvedValue({} as Utilisateur);
        jest.spyOn(jwtMock, 'sign').mockReturnValue('fake-token' as never);

        const res = mockRes();
        const result = await service.login(
            { email: 'test@gmail.com', password: 'motdepasse123' },
            res,
        );

        expect(result.userId).toBe('uuid-valide');
        expect(result.role).toBe('client');
        expect(res.cookie).toHaveBeenCalledTimes(2); // access_token + refresh_token
    });

});
```

`login` reçoit un `Response` Express en paramètre — on ne peut pas passer `undefined`. Il faut un **mock de réponse**. Ajoute cette fonction utilitaire **en dehors** des `describe`, juste en dessous des imports :

```typescript
import * as bcrypt from 'bcrypt';
import type { Response } from 'express';

function mockRes(): Response {
    return {
        cookie: jest.fn(),
        clearCookie: jest.fn(),
    } as unknown as Response;
}
```

Ajoute aussi dans les imports NestJS :

```typescript
import { BadRequestException, ConflictException, ForbiddenException, NotFoundException, UnauthorizedException } from '@nestjs/common';
```

## Étape 9 — `logout` : 1 cas

C'est le plus court — une seule règle à vérifier :

```typescript
describe('logout', () => {

    it('devrait effacer le refresh token en base et vider les cookies', async () => {
        const prismaMock = module.get<PrismaService>(PrismaService);

        const updateSpy = jest
            .spyOn(prismaMock.utilisateur, 'update')
            .mockResolvedValue({} as Utilisateur);

        const res = mockRes();
        const result = await service.logout('uuid-utilisateur', res);

        expect(result.message).toContain('Déconnecté');
        expect(updateSpy).toHaveBeenCalledWith({
            where: { id: 'uuid-utilisateur' },
            data: { refresh_token_hash: null },
        });
        expect(res.clearCookie).toHaveBeenCalledWith('access_token');
        expect(res.clearCookie).toHaveBeenCalledWith('refresh_token');
    });

});
```

## Synthèse
Voici ce qu'on a testé et **pourquoi chaque cas compte** :

|Méthode|Cas|Règle métier protégée|
|---|---|---|
|`register`|email en double|pas deux comptes avec le même email|
|`register`|inscription réussie|email de confirmation bien envoyé|
|`confirmEmail`|token inconnu|pas d'activation sur un lien inventé|
|`confirmEmail`|token expiré|lien valable 48h seulement|
|`confirmEmail`|token valide|compte activé + token effacé|
|`login`|email inconnu|message d'erreur générique (pas d'énumération)|
|`login`|mauvais mot de passe|idem|
|`login`|compte inactif|impossible de se connecter sans confirmer|
|`login`|credentials valides|2 cookies posés, userId + role retournés|
|`logout`|appel valide|refresh token null + cookies effacés|
