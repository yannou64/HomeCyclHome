# 14. Composant Carousel

> **Fichiers concernés**
> - `src/shared/components/Carousel/Carousel.tsx`
> - `src/shared/components/Carousel/Carousel.module.scss`

---

## Ce que fait ce composant

Le `Carousel` affiche une série d'images qui défilent automatiquement de droite à gauche, en boucle infinie, sans interaction utilisateur. L'animation est entièrement gérée en **CSS pur** — pas de JavaScript, pas de librairie externe.

---

## Le principe de la boucle infinie seamless

C'est le cœur technique du composant. Le problème à résoudre : comment faire défiler des images sans qu'on voie le "saut" quand l'animation repart au début ?

**La solution : dupliquer les images.**

```typescript
const loopedImages = [...images, ...images];
//                    [A, B, C,   A, B, C]
//                    ← original → ← copie →
```

On place deux fois le même jeu d'images côte à côte. L'animation fait glisser le tout de `0` vers `-50%` de la largeur totale :

```
Début :  [A][B][C][A][B][C]
         ↑ visible

Milieu : [A][B][C][A][B][C]
               ↑ visible

Fin :    [A][B][C][A][B][C]
                  ↑ on est revenu exactement à l'image A
         → l'animation repart depuis le début : seamless
```

À `-50%`, on a défilé exactement un jeu complet et on se retrouve visuellement au même point qu'au départ. La transition est invisible.

---

## L'animation CSS `@keyframes`

```scss
@keyframes scrollLeft {
    from { transform: translateX(0); }
    to   { transform: translateX(-50%); }
}

.track {
    animation: scrollLeft linear infinite;
    // La durée est injectée depuis le composant via style inline
}
```

**Décomposition :**
- `@keyframes scrollLeft` : définit l'animation nommée "scrollLeft"
- `from / to` : synonymes de `0%` et `100%`
- `translateX(-50%)` : décale l'élément de 50% de sa propre largeur vers la gauche
- `linear` : vitesse constante (pas d'accélération ni de décélération)
- `infinite` : répète indéfiniment

**Pourquoi `transform: translateX()` et pas `margin-left` ou `left` ?**
`transform` est traité par le GPU du navigateur et ne déclenche pas de **reflow** (recalcul du layout). C'est la propriété CSS la plus performante pour les animations. `margin-left` et `left` forcent un recalcul complet du layout à chaque frame — coûteux sur mobile.

---

## La durée configurable via `style` inline

```tsx
<div
    className={styles.track}
    style={{ animationDuration: `${speed}s` }}
>
```

La vitesse est une prop (`speed?: number`, défaut 25s). On l'injecte via `style` inline plutôt que de la mettre en SCSS parce que c'est une **valeur dynamique** : elle vient des props et peut changer selon le contexte d'utilisation.

Règle pratique :
- **Valeur statique** → SCSS
- **Valeur dynamique** (calculée, venue des props) → `style` inline ou CSS custom property

---

## La structure du track et des slides

```scss
.carousel {
    width: 100%;
    height: 100%;
    overflow: hidden;   // masque tout ce qui dépasse à droite
}

.track {
    display: flex;          // images côte à côte
    height: 100%;
    width: max-content;     // largeur = somme de toutes les images
    animation: scrollLeft linear infinite;
}

.slide {
    height: 100%;
    width: auto;            // garde le ratio naturel de l'image
    object-fit: cover;
    flex-shrink: 0;         // empêche la compression
}
```

**`width: max-content` sur `.track`** : indique au navigateur de laisser le conteneur aussi large que nécessaire pour placer toutes les images sans retour à la ligne. Sans ça, flex essaierait de compresser les images dans la largeur disponible.

**`flex-shrink: 0` sur `.slide`** : par défaut, les enfants flex se compressent si l'espace manque. On force chaque image à garder sa largeur naturelle.

**`object-fit: cover` sur `.slide`** : si une image n'a pas exactement la bonne hauteur, elle est rognée proprement plutôt que déformée.

---

## `aria-hidden="true"` — accessibilité

```tsx
<div className={styles.carousel} aria-hidden="true">
```

Le carousel est purement décoratif. Un utilisateur de lecteur d'écran n'a pas besoin qu'on lui annonce "image de réparation vélo, image de réparation vélo, image de réparation vélo..." en boucle. `aria-hidden="true"` demande aux technologies d'assistance d'ignorer complètement cet élément.

---

## Généricité — pourquoi les images sont des props

```typescript
type CarouselProps = {
    images: string[];    // tableau d'URLs (ou chemins importés)
    alt?: string;        // texte alternatif commun (optionnel, décoratif ici)
    speed?: number;      // secondes par cycle (défaut : 25)
};
```

Le `Carousel` ne sait pas ce qu'il affiche. Il reçoit des URLs et les fait défiler. Cette séparation permet de réutiliser le composant dans n'importe quel contexte :

```tsx
// Carousel de réparations (dans PageLayout)
<Carousel images={[reparationMobile, reparationDesktop]} speed={30} />

// Carousel de partenaires (dans une autre page future)
<Carousel images={[logoPartenaire1, logoPartenaire2, logoPartenaire3]} speed={15} />
```

Le comportement (défilement) est dans `Carousel`. Les données (quelles images) sont dans le parent. C'est le principe de **séparation des responsabilités** appliqué aux composants.

---

## Enrichir le carousel plus tard

Quand de nouvelles photos de réparation seront disponibles, il suffit de les ajouter au tableau dans `PageLayout.tsx` :

```typescript
const CAROUSEL_IMAGES = [
    reparationVeloMobile,
    reparationVeloDesktop,
    // reparationVelo3,   ← ajouter ici
    // reparationVelo4,
];
```

Le composant `Carousel` n'a pas à changer. La durée de l'animation (`speed={30}`) peut également être ajustée pour compenser l'ajout d'images et maintenir un rythme de défilement cohérent.
